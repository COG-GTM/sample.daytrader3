## Test result (iteration log)

### Iteration 1
Two compile/runtime issues surfaced and were fixed (no tests disabled/skipped):

1. `getHoldings(...)` returns `Collection<?>`; test used a generic mismatch → fixed
   the test to cast the element.
2. Entity persistence: `AccountProfile`/`Account` insert ordering and the
   `@OneToOne` order→holding **unique** constraint generated by Hibernate broke the
   buy-then-sell path. Fixed by (a) `cascade = ALL` on the inverse
   `AccountProfileDataBean.account` so the profile/account pair persists in FK order,
   and (b) driving the schema from `schema.sql` with `ddl-auto=none` to preserve the
   legacy non-unique `HOLDING_HOLDINGID` column (see Phase 7).

## Tests added

`TradeServiceImplTest` (`@SpringBootTest`, transactional rollback, H2) covers
register/duplicate-register, login/logout, bad-password failure, quote create/lookup,
buy (holding created + balance debited), sell (holding removed + balance credited),
order listing, market summary (TSIA + top movers), profile update, and that the
deferred JMS/reset paths raise `UnsupportedOperationException`.

`TradeControllerTest` (`@SpringBootTest` + `MockMvc`) exercises the REST endpoints
end-to-end: register → login → create quote → get quote → buy → list holdings.

## Manual startup verification (evidence)

`mvn spring-boot:run` → `Started DayTraderApplication … Tomcat started on port 8080`.
REST smoke test:
- `POST /api/register` → account with `balance=100000.00`.
- `POST /api/quotes` (s:100 @ 25.00) → quote created.
- `POST /api/accounts/uid:0/buy?symbol=s:100&quantity=10` → order `closed`,
  account `balance=99725.05` (= 100000 − 10×25 − 24.95 fee).
- `GET /api/accounts/uid:0/holdings` → 1 holding of 10 shares.

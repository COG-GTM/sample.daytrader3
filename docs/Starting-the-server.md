You can use [Gradle](#running-with-gradle) or [Maven](#running-with-maven) to control and manipulate the Open Liberty server for use in automated builds to support continuous integration.

## Running with Gradle

The [Liberty Gradle plugin](https://github.com/OpenLiberty/ci.gradle) can manage the server using the following tasks:

* `libertyStart` / `libertyStop` start and stop the server in the background.
* `libertyRun` runs the server in the foreground.
* `libertyStatus` checks whether the server is running.
* `installLiberty` / `installFeature` download Open Liberty and install the features listed in `server.xml`.
* `deploy` copies the ear into the server's `apps` directory.

## Running with Maven

The [Liberty Maven plugin](https://github.com/OpenLiberty/ci.maven) can manage the server using the following goals (run them from the `daytrader3-ee6` directory):

* `liberty:start` / `liberty:stop` start and stop the server in the background.
* `liberty:run` runs the server in the foreground.
* `liberty:status` checks whether the server is running.
* `liberty:install-server` / `liberty:install-feature` download Open Liberty and install the features listed in `server.xml`.
* `liberty:deploy` copies the ear into the server's `apps` directory.

## Additional Notes

:star: *Note:* The Maven clean target and Gradle clean task will clean server output (logs and workarea, etc) from the daytrader3-ee6-wlpcfg directory, however, if you wanted to maintain strict separation between what is checked into daytrader3-ee6-wlpcfg and what is generated by a running server, you could also specify the WLP_OUTPUT_DIR environment variable, e.g. into the maven target directory.

```bash
$ export WLP_OUTPUT_DIR=${WLP_USER_DIR}/target
```
